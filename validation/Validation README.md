# validation/ — evidence bundle

Two campaigns live here, using two different signals. Read §1 before comparing
any numbers across them.

**Start here:** `phi_validation_note_EN.pdf` — technical note on the Tinker
campaign: supported claims, falsified claims, thresholds, seed protocols,
baseline comparison, open questions.

## 1. Two signals, two scales

| | **φ_jump** (Tests 5–7) | **φ_dev** (Tests 8–14) |
|---|---|---|
| Definition | `EMA_0.8(max(0, Δloss))` | `EMA( abs(loss − EMA(loss)) + 0.5·max(0, Δloss) )` |
| Typical healthy value | ~0.011 | ~1.9 |
| Threshold | fixed, 0.10 | adaptive, `μ + k·σ` |
| Platform | Qwen3-8B via Tinker API | Qwen2.5-0.5B-Instruct, single T4 |
| Implemented in | `test5–7*.py` (self-contained) | `orbital_controller.py` |

Thresholds do not transfer between them. The 0.10 figure is meaningless for
φ_dev.

## 2. Campaign A — φ_jump on Tinker (Tests 5–7)

Threshold 0.10 fixed from Test 5, reused unchanged in Tests 6–7. Verdict
criteria, including failure conditions, are pre-registered inside **these
three scripts** (this does not hold for the Test 8–14 scripts).

| File | Contents | Regenerated by |
|---|---|---|
| `phi_validation_note_EN.pdf` / `.md` | Technical note — read first | — |
| `phi_natural_stress_log.json` | Test 5 **summary**: 6 aggregated rows (3 seeds × {healthy, stressed}), fields `phi_mean`, `phi_max`, `loss_std`, `nan_count`. Not per-step traces. | `test5_natural_stress.py` |
| `phi_blind_diagnostic.json` | Test 6: blind classification, 10/12, with confusion matrix. **Reconstructed from printed run output**, not written natively by the script. | `test6_blind_diagnostic.py` |
| `phi_lead_time_log.json` | Test 7: per-step traces `[step, loss, φ, lr]` for all 14 runs (8 LR-ramp + 6 healthy), plus the pre-registered criteria block | `test7_phi_lead_time_v2.py` |
| `test7_reanalyze.py` | Offline reanalysis of Test 7 — no API credits needed | — |
| `fig_summary.png`, `fig_test7_runs.png` | Figures | — |

**Results.** 371× healthy-vs-unstable separation (3 seeds); 10/12 blind
classification, 10/10 at the extremes; 0 false alarms across 6 healthy runs of
300 steps; detection 1–2 steps *after* collapse begins.

**Void verdict.** Test 7's predictive lead-time test is declared void: the
task saturated to near-zero loss, so no loss-derived signal could show
precursors. Corrected protocol v3 declared in the note, not yet run.

**Loss-only, verified.** φ values in `phi_lead_time_log.json` match the pure
loss-derived EMA to within 6e-14, confirming no gradient information entered
the validated signal. (`PhiMonitor` accepts an optional `grad_norm` term at
weight 0.01; Tinker did not expose it, so it stayed inert.)

These scripts run the actual repository controller (`OrbitalController` +

### Results

**Test 12 — actuator disabled.** Per-seed shock/control φ_dev ratios
3.32 / 7.36 / 4.34 / 5.51 / 8.27 (mean 5.76×). Adaptive detector `μ + 1.5σ`:
5/5 hits, 0 pre-onset alarms, 0 false positives, mean latency 0.8 steps. Clean
operating interval for k spans 1.1 to 4.7 (37 values with perfect accounting);
it breaks at k=5.0. An absolute threshold calibrated leave-one-seed-out
(margin ×1.25) also reaches 5/5 with 0 false positives, latency 2.2 — so the
result does not depend on one detector family.

**Test 10 / 14 — actuator enabled, seed 11.** At the default
`stable_window=30` the LOW state never fires. At `stable_window=10` or `5` it
fires 4 steps after shock onset. Same-seed paired ratio drops from 3.32×
(actuator off) to 2.13× (on).

Test 14, `stable_window=10`, both arms per k:

| k | shock: first LOW | latency | control: first LOW | valid operating point |
|---|---|---|---|---|
| 0.1 | 84 | 4 | 109 | no — false positive |
| 1.5 | 84 | 4 | none | yes |
| 6.0 | 84 | 4 | none | yes |

`stress_k` is not inert (k=0.1 gives a different trajectory: φ 4.404, 6
transitions vs 3.892, 8). The identical `first_low` across k is the hysteresis
gate: by the time the FSM is allowed to evaluate, raw φ is far above every
threshold in this range. The k=1.5 run reproduces Test 10 exactly (φ=3.892,
8 transitions, LOW at 84), confirming the pipeline is deterministic.

### Reading these results

Detection with the actuator enabled is **degraded, not destroyed**: valid
operating points exist. The contamination effect is a loss of latency and
separation, plus outright failure at the shipped default `stable_window=30`.

## 4. Confounds that limit Campaign B

1. **The task saturates.** 20 fixed prompt/target pairs over 200 steps is ten
   epochs on the same material. Control-arm loss: 0.41 (steps 80–119) → 0.017
   (120–159) → 0.004 (160–199). So the comparison is *corrupted targets vs
   memorised task*, not *unstable vs healthy training*. A detector firing on
   "loss is not near zero" would score equally well. Every ratio and detection
   figure above is an upper bound. Fixing this — a pool large enough that 200
   steps is not ten epochs — requires rerunning Tests 10, 12 and 14.
2. **Logged φ_dev ≠ acting φ_dev.** `get_summary()["phi"]` returns the
   smoothed `phi_ema`; the FSM compares the raw per-step φ against `μ + k·σ`.
   At one shock step the trace records 4.52 where the controller saw 17.8.
   Offline reanalysis of these traces therefore does **not** reproduce the
   controller's decisions, `test12_reanalyze.py` included.
3. **Missing logs.** Tests 8, 9, 11 and 13 have no committed logs; their
   numbers are currently unauditable. The AdaLoRA control case (Test 13) is
   the most consequential gap, since it is what bounds the contamination
   claim.
4. **Single seed** for Tests 8, 10 and 14. The k=0.1 control-arm false
   positive is unreplicated.
5. **Fixed shock onset** at step 80; latency figures will not survive
   randomised onset.
6. **Test 10's verdict block had a reporting bug**, fixed in Test 14: it
   counted LOW activations in shock arms only and never checked whether the
   control arm also fired, so a false positive read as a success. It also
   computed "latency" for the control arm relative to step 80, where no shock
   exists.

## 5. Reproducing without a GPU

`traces_phi_clean.json` + `test12_reanalyze.py` regenerate the full Test 12
detector accounting in seconds, no GPU and no API key. Same for
`test7_reanalyze.py` against `phi_lead_time_log.json`.

Campaign A scripts need a Tinker API key (`TINKER_API_KEY`). Campaign B
scripts need a GPU; each 200-step run takes roughly 8–10 minutes on a T4.
